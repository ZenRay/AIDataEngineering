一个仓库，多个工作目录，并行开发利器

核心概念：什么是 Worktree？

📦 .git/ (唯一的仓库数据库)
↓
📁 AIDataEngineering
分支: dw-poc

主工作目录
当前正在开发的功能

📁 AIDataEngineering-mcp
分支: master

Worktree #1
用于紧急修复/Review

📁 AIDataEngineering-learn-worktree
分支: learning/worktree-demo

Worktree #2
学习专用

✅ 关键优势：
  • 共享同一个 .git 仓库，节省磁盘空间
  • 每个 worktree 有独立的工作目录，互不干扰
  • 无需频繁 stash/checkout，可以同时工作
  • commit、push、pull 在所有 worktree 中都能工作

工作流程：创建和使用 Worktree

1
创建 Worktree
git worktree add
2
初始化环境
submodule + direnv
3
并行开发
独立工作、提交
4
清理
git worktree remove
git worktree add ../AIDataEngineering-hotfix -b hotfix/urgent-fix
cd ../AIDataEngineering-hotfix && git submodule update --init && direnv allow
# 在 worktree 中工作... commit... push...
git worktree remove ../AIDataEngineering-hotfix

对比：Worktree vs 传统方式

操作 传统方式 (stash + checkout) Worktree 方式
切换分支 stash → checkout → 工作 → checkout → stash pop cd 到另一个 worktree 目录即可
同时运行多个分支 ❌ 不可能 ✅ 可以，每个 worktree 独立
上下文保持 容易丢失，需要频繁切换 完美保持，各工作目录独立
未提交更改 需要 stash 或 commit 可以留在原地，不受影响
磁盘占用 单个工作目录 多个工作目录，但共享 .git

实战场景

场景 1：紧急修复线上 Bug

📁 你正在开发 feature
feature/my-feature

开发到一半...

🚨
📁 紧急创建 hotfix worktree
master

快速修复并部署

git worktree add ../AIDataEngineering-hotfix master

场景 2：Review 同事的分支

📁 Review worktree
feature/colleague-branch

可以运行、测试、调试

git fetch origin
git worktree add ../AIDataEngineering-review origin/feature/colleague-branch

⚠️ 重要注意事项

🔴 不能有两个 worktree 检出同一分支

这会防止冲突，是 Git 的保护机制。

💡 Submodule 需要手动初始化

新创建的 worktree 不会自动初始化 submodule，需要执行：

git submodule update --init --recursive
💡 direnv 需要单独 allow

每个 worktree 都需要单独执行 direnv allow
